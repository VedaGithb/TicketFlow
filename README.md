# TicketFlow

Высоконагруженный сервис бронирования билетов на мероприятия в условиях пикового спроса (Flash Sale).

Проект решает классическую проблему конкурентности при ажиотажных продажах: тысячи пользователей одновременно нажимают «Купить» на ограниченное количество мест. Архитектура гарантирует строгую целостность данных, нулевой овербукинг и отсутствие взаимных блокировок базы данных (дедлоков).

---

## Стек технологий

* **Язык и среда:** Node.js, TypeScript (строгий режим, zero `any`)
* **Веб-фреймворк:** Fastify 5 (плагинная архитектура, нативная валидация схем)
* **СУБД:** PostgreSQL 16 + Drizzle ORM (ACID транзакции, строгие типы, миграции)
* **Быстрое хранилище и брокер:** Redis 7 + ioredis (кэш, распределенные локи, Pub/Sub)
* **Очередь задач:** BullMQ (отложенные задачи автоматической отмены неоплаченной брони)
* **Real-Time:** WebSockets (`@fastify/websocket`) с группировкой по комнатам
* **Мониторинг:** Prometheus (`prom-client`) + Grafana (RPS, latency p95/p99)
* **Безопасность:** `@fastify/rate-limit` на базе Redis, валидация через Zod
* **Документация:** Swagger / OpenAPI (`@fastify/swagger`, `@fastify/swagger-ui`)
* **Инфраструктура:** Docker, Docker Compose
* **Нагрузочное тестирование:** k6 (Grafana Labs)

## Архитектурные решения

### 1. Защита от Race Condition и дедлоков (Deadlock Prevention)
* Блокировка мест на уровне строк: `SELECT ... FROM seats WHERE id IN (...) ORDER BY id FOR UPDATE`.
* **Устранение дедлоков:** массив запрашиваемых ID мест детерминированно сортируется перед запросом (`[...seatIds].sort()`). Это исключает ситуацию «циклического ожидания» (Circular Wait), когда две параллельные транзакции блокируют места во встречном порядке.

### 2. Идемпотентность платежей и заказов (Idempotency Key)
* Каждый запрос на бронирование передает заголовок `Idempotency-Key: <uuid>`.
* В Redis атомарно выставляется блокировка через `SET key PROCESSING EX 120 NX`.
* При повторном клике (дабл-клик, сетевой сбой) сервер не списывает деньги повторно, а возвращает закешированный результат предыдущей успешной обработки.

### 3. Transactional Outbox Pattern (Защита от Dual-Write)
* Создание брони и создание отложенного события на отмену (`BOOKING_CREATED`) происходят в **единой неделимой транзакции PostgreSQL**.
* Отдельный фоновый процесс **Outbox Relay** вычитывает события из таблицы `outbox_events` пачками с использованием `FOR UPDATE SKIP LOCKED` и надежно отправляет задачи в очередь **BullMQ**.
* Даже при падении Redis или сбое сети задачи не теряются и гарантированно доставляются (гарантия At-Least-Once).

### 4. Real-Time синхронизация зала через WebSockets + Redis Pub/Sub
* Клиенты подключаются к сокет-комнате конкретного события: `ws://host/events/:id/live`.
* **Ленивая подписка (Lazy Subscription):** Redis начинает слушать канал зала только тогда, когда в него зашел первый зритель, и автоматически отписывается, когда зал пустеет.
* При выкупе (`LOCKED`) или истечении брони (`RELEASED`) бродкастится только дельта изменений (массив ID мест со статусом), исключая тяжелые `SELECT`-запросы к PostgreSQL.
* Серверный **Heartbeat (Ping-Pong)** каждые 30 секунд очищает зависшие и мертвые соединения без утечек памяти.

### 5. Production Hardening
* **Graceful Shutdown:** перехват сигналов `SIGINT` и `SIGTERM` — сервер прекращает прием входящих запросов, дожидается завершения текущих транзакций, корректно останавливает воркеры BullMQ и закрывает пулы PostgreSQL и Redis.
* **Rate Limiting:** ограничение агрессивных запросов через `@fastify/rate-limit` со счетчиками в Redis (защита от ботов и перекупщиков).

## Быстрый старт

### 1. Предварительные требования
* Node.js 20+
* Docker и Docker Compose

### 2. Клонирование и установка зависимостей
```bash
git clone https://github.com/VedaGithb/TicketFlow.git
cd TicketFlow
npm install
```

### 3. Запуск инфраструктуры (PostgreSQL, Redis, Prometheus, Grafana)
```bash
docker compose up -d
```

### 4. Накатывание миграций и сид данных
```bash
npm run db:migrate
npx tsx src/db/seed.ts
```

### 5. Запуск сервера в dev-режиме
```bash
npm run dev
```
Сервер запустится на `http://localhost:4000`.

## API Эндпоинты

| Метод | Путь | Описание |
| :--- | :--- | :--- |
| `POST` | `/bookings` | Создание брони с заголовком `Idempotency-Key` |
| `GET` | `/events/:id/live` | WebSocket-канал реального времени для зала |
| `GET` | `/docs` | Интерактивная Swagger/OpenAPI документация |
| `GET` | `/health` | Healthcheck сервиса |
| `GET` | `/metrics` | Метрики для сбора Prometheus |
